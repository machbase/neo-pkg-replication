# 문제 해결

이 문서는 화면에서 자주 만나는 문제 상황과 점검 순서를 정리한 것입니다.

## 1. Source 서버가 선택 목록에 보이지 않음

가능한 원인:

- 아직 서버를 등록하지 않음
- Source로 사용할 수 없는 유형임

확인 방법:

1. Server Settings를 엽니다.
2. 서버가 실제로 등록되어 있는지 확인합니다.
3. 연결 테스트가 성공하는지 확인합니다.

참고:

- `mqtt-api`, `mqtt-publish`는 Target 전용으로 보는 것이 맞습니다.

## 2. 테이블 목록이 비어 있음

가능한 원인:

- 서버 연결은 되었지만 해당 계정으로 테이블 조회가 안 됨
- 잘못된 서버 또는 포트를 선택함
- 대상 테이블이 아직 생성되지 않음

점검 순서:

1. Server Settings에서 연결 테스트를 다시 수행합니다.
2. 올바른 서버를 선택했는지 확인합니다.
3. 실제 Source / Target DB에 테이블이 존재하는지 확인합니다.

참고:

- Target이 `mqtt-publish`라면 테이블 목록 대신 Topic 입력 칸이 보이는 것이 정상입니다.

## 3. Target이 mqtt-publish일 때 저장이 안 됨

가능한 원인:

- Topic 형식이 유효하지 않음

점검 방법:

- Target Database에서 Topic 값을 다시 확인합니다.
- 공백, `+`, `#` 문자가 들어가 있지 않은지 확인합니다.
- 앞이나 뒤가 `/`로 시작하거나 끝나지 않는지 확인합니다.
- 영문자, 숫자, `.`, `_`, `-`, `/` 조합으로 다시 입력해 봅니다.

## 4. 저장할 때 Validation Warnings가 뜸

이 창은 저장 불가 오류와는 다릅니다.  
즉시 중단해야 하는 상황이 아니라, 사용자가 한 번 더 확인해야 하는 상황입니다.

권장 대응:

1. 경고 문구를 읽습니다.
2. Source / Target 매핑과 조건을 다시 확인합니다.
3. 의도한 설정이 맞다면 `Save Anyway`를 사용합니다.

## 5. Job이 생성됐는데 바로 시작되지 않음

가능한 원인:

- Job 설정은 생성됐지만 서비스 등록이 완료되지 않음
- 일시적인 설치 오류나 운영 환경 차이로 config-only 상태로 남아 있음

확인 방법:

- 사이드바에서 해당 Job 오른쪽에 `Register` 버튼이 보이는지 확인합니다.
- 일반적으로는 Job 생성 후 바로 실행되므로, `Register` 버튼이 보이면 예외 상황으로 보는 것이 맞습니다.
- `Register`를 눌러 서비스 등록을 다시 시도합니다.
- 등록 후 스위치가 나타나면 그때 정상적으로 시작/정지할 수 있습니다.

## 6. Edit 또는 Delete 버튼이 동작하지 않음

가능한 원인:

- Job이 실행 중임

권장 순서:

1. 먼저 Job을 정지합니다.
2. 정지 상태가 확인되면 Edit 또는 Delete를 다시 시도합니다.

## 7. 대시보드에 warning이 표시됨

대표적인 원인:

- Source 테이블 삭제 또는 변경
- Target 테이블 삭제 또는 변경
- 현재 row count 조회 실패

점검 순서:

1. 경고 문구를 읽습니다.
2. Source / Target 서버와 테이블이 실제로 존재하는지 확인합니다.
3. Live Logs에서 현재 오류가 계속 발생하는지 확인합니다.
4. 필요하면 Log Files에서 과거 로그를 열거나 다운로드해서 확인합니다.

## 8. 데이터가 기대보다 적게 복제됨

가능한 원인:

- `Replication Target Condition`이 좁게 설정됨
- Data Pipeline Builder에서 필터가 적용됨
- `Start Mode`를 `Now`로 설정함

확인 항목:

- `ALL`, `IN`, `LIKE` 중 무엇을 선택했는지
- Pipeline에서 `filter`가 들어 있는지
- 처음부터 복제해야 하는데 `Now`를 사용하지 않았는지

## 9. 로그가 너무 많거나 파일이 너무 빨리 쌓임

가능한 원인:

- 로그 레벨이 너무 낮음
- File Limit이 너무 큼

권장 조정:

- 일반 운영은 보통 `INFO` 또는 `WARN` 수준에서 시작합니다.
- 필요한 경우에만 `DEBUG` 또는 `TRACE`를 사용합니다.

## 10. Live Logs가 비어 있거나 연결되지 않음

가능한 원인:

- Job이 아직 실행 중이 아님
- 아직 새 로그가 발생하지 않음
- 로그 파일이 아직 생성되지 않았거나 연결이 잠시 끊김

확인 순서:

1. Job 상태가 `running`인지 확인합니다.
2. Live Logs 상단의 연결 상태가 `CONNECTED`인지 확인합니다.
3. 현재 로그가 거의 발생하지 않는 작업인지 확인합니다.
4. 필요하면 Log Files에서 기존 로그 파일이 있는지 확인합니다.

## 11. 로그 파일을 보관하거나 전달해야 함

권장 방법:

1. Log Files를 엽니다.
2. 필요한 파일의 다운로드 버튼을 누릅니다.
3. 다운로드한 파일로 상세 분석이나 전달을 진행합니다.

## 12. Source 또는 Target을 바꾼 뒤 설정이 달라져 보임

이 동작은 비정상이 아닐 수 있습니다.

화면 동작 특성:

- 서버를 바꾸면 테이블 선택이 초기화될 수 있습니다.
- 테이블을 바꾸면 컬럼 매핑이 초기화될 수 있습니다.
- Source 테이블을 바꾸면 Data Pipeline Builder 규칙이 초기화될 수 있습니다.

따라서 Source/Target을 변경한 뒤에는 다음을 다시 확인해야 합니다.

- 테이블 선택
- Column Mapping
- Replication Target Condition
- Data Pipeline Builder

## 운영자가 기억하면 좋은 체크리스트

- 먼저 Server 연결 테스트를 본다.
- 그다음 Source/Target 테이블 존재 여부를 본다.
- 그다음 대시보드 경고와 row count를 본다.
- 마지막으로 로그 파일을 본다.
